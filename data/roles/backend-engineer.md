# Rubric — Backend Engineer

Seeded by `/screen-candidate` on first use. Edit freely — this is a starting
point, not a fixed spec.

## Must-haves

- **Production ownership** — has owned a service end-to-end in production
  (not just contributed to one), including on-call or operational responsibility.
- **Python backend depth** — solid, evidenced experience with a Python web
  framework (FastAPI/Django/Flask) and a relational database.
- **Testing discipline** — concrete evidence of writing or improving automated
  test coverage, not just "wrote tests" as a throwaway line.
- **System design at service scale** — has done more than CRUD: a migration,
  a decomposition, an event-driven or async architecture decision.

## Nice-to-haves

- Experience with a message queue / event streaming system (Kafka, SQS, etc.).
- Open-source contributions, especially merged PRs fixing non-trivial bugs
  (concurrency, correctness) rather than docs/typo fixes.
- Experience with LangChain/LangGraph or LLM-agent tooling (this repo's stack).
- Comfort with or explicit interest in design docs / RFC-driven change process.

## Red flags

- Vague ownership claims ("worked on", "involved in") with no concrete system
  or outcome named.
- No evidence of operational responsibility (on-call, incident response,
  production debugging) for a "senior" title.
- Testing mentioned only in passing, or absent entirely.
- Job-hopping under 12 months per role with no explanation, or unexplained gaps.
